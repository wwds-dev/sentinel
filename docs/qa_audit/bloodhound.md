## 1. Verdict

The file-discovery core is the strongest part of Bloodhound and mostly keeps its word: remote search uses `load_system_host_keys()` plus `paramiko.RejectPolicy()` (no AutoAdd anywhere), passes `password=None`, persists and logs no host, credential or key, reads metadata only (`scandir`/`stat`, `listdir_attr`), skips every symlink, stops at exactly the documented 5,000 matches / 250,000 entries, and checks cancellation between folders and between entries. There is no code path that carries file-discovery paths or results into a model request. The product is not ready for the test phase, though, for four reasons. (1) The dossier-side promises the manual test plan relies on are thin: provider results are never shown, failed providers are only visible if the model mentions them, a worker-level collection failure silently discards everything, "evidence / inference / unknowns" and lawful-use guidance exist only as prompt requests, and Stop in the model phase ends as "Error" and can still bill. (2) File discovery is not wired into the window Stop button, app close or Emergency Reset, and double-click reveal is broken for remote results (it tests the local filesystem). (3) Privacy and cost handling contradicts the docs: EXIF including GPS coordinates and the image filename is auto-injected into the prompt sent to the default paid cloud model, which contradicts the training lesson ("never send ... extracted metadata to a cloud model unless ... explicitly approved"); public-source contact has no consent step; and the pre-flight cost gate prices only the target string. (4) `~/.ssh/config` is only partly honoured (config User/Port override the panel, IdentityFile/IdentityAgent/ProxyJump are ignored), and TIFF/BMP/HEIC images offered by the file dialog are silently reported as "no EXIF, may have been stripped". Documentation and tooltips have also drifted (nonexistent file paths and function names, "collapsed" image section and "Model override" that do not exist, "locally" and "registered destination" wording).

### (c) Undocumented behaviour

**EXIF: what is extracted and where it goes (focus item).**
- Parsing: `PIL.Image.open(path)._getexif()` (panel:42-43). Only JPEG, PNG and WebP expose it; other formats silently yield `{}` (row 5). All tags of str/int/float/bytes type are kept in memory (panel:47-52); GPSInfo is expanded to named tags (panel:49-50).
- Local display (panel:68-88, 992-1044): date, make/model, software, lens, size, orientation, flash, focal length, decimal GPS, with map and sun-angle links.
- Sent to the model (panel:91-112 via agent:558-564): the file name; the allow-listed tags DateTimeOriginal, DateTime, Make, Model, Software, LensMake, LensModel, ImageWidth, ImageLength, Orientation, Flash, FocalLength; GPS lat/lon, a Google Maps URL, altitude and camera direction. Not forwarded: MakerNote, UserComment, Artist, Copyright, thumbnails and other tags (good). Image bytes are never read into a request.
- Destination: whichever provider the run bar shows (default Anthropic claude-opus-5-5), in the same user message as the target and live data. After the response, the target and dossier are saved to history (main.py:3666-3673); the EXIF block is not stored in history (messages=None path stores only `context["prompt"]`, the target).
- `gps_to_decimal` returns 0.0 for unreadable values (panel:58-65), so a malformed GPS tag is passed to the model as "GPS Coordinates: 0.0, 0.0" with a Maps link, as if it were evidence.
- Image filename and EXIF text values are interpolated unescaped into HTML for a `QTextBrowser` with `setOpenExternalLinks(True)` (panel:231-235, 1012, 1022). A crafted image (EXIF Software/Model, or file name containing markup) can inject clickable links into the investigator's pane.

**Network and consent.**
- Clicking Investigate immediately sends the target (an email address in clear text) to every applicable public service. There is no consent dialog naming destinations, unlike Trace (M L56-59). With Ollama selected no dialog of any kind appears (main.py:3463-3465). The execution-mode box ("Local only") is never consulted by this panel, so live collection still runs.
- A Deep Dive on a username makes about 600 direct requests from the user's IP using a spoofed browser User-Agent (whatsmyname.py:56-59); documented as "requested directly from this Mac" but not as needing confirmation.
- `dns.resolver` queries (domain_lookup.py:103-117) and python-whois contact the target's name servers and registry, which is active contact the docs describe as passive public-source collection.
- `refresh_in_background()` downloads the OSINT Framework catalogue when the panel first shows (panel:494-498); documented.

**Cost and logging.**
- Cost gate prices only the target (row 88).
- The run log keeps the target for every run (services/run_logger.py:22); Saved Chats keep the target and the full dossier. File discovery is not logged anywhere (good).

**Prompt-injection / trust.**
- Third-party free text (GitHub and Keybase bios, Gravatar description, URLScan titles, ransomware.live descriptions, Ahmia snippets, CourtListener party names, IntelX record names) is serialised as JSON into the user message under "confirmed, verified fact" framing (agent:537-556) with no delimiting beyond JSON. A hostile profile can steer the dossier.
- `SectionCard` renders the body with `QLabel` in Qt auto-text mode (ui/widgets.py:686-691), so HTML in model or third-party text is interpreted as rich text (links are not clickable there).

**SSH / file-search mechanics.**
- Config `User`/`Port` override the panel; `IdentityFile`, `IdentityAgent`, `ProxyJump`, `UserKnownHostsFile` ignored; `ProxyCommand` runs a local subprocess (remote_file_search.py:48-52). If `connect` fails, the client and ProxyCommand socket are never closed (:57-68 sits outside the try/finally at :97-150).
- Only `~/.ssh/known_hosts` is consulted, so the first connection to a new host requires the user to connect once with a normal ssh client (or via Open SSH Terminal) before Sentinel will accept it; no UI text explains this.
- No timeout on SFTP operations; paramiko errors other than OSError/IOError/socket.error (e.g. `SSHException`, `EOFError` on a dropped link) escape the per-folder handler, abort the search, and the error dialog replaces results, so matches found so far are lost (workers.py:388-389 emits only the error).
- `datetime.fromtimestamp` is called outside any try/except (local_file_search.py:74, 148; remote_file_search.py:142). A file with an out-of-range mtime (or a hostile SFTP server reporting one) raises ValueError/OverflowError and aborts the entire search with all matches discarded.
- A server that omits `st_mode` yields entries that match no branch and are silently skipped (remote_file_search.py:120-127).
- Symlinked files are never listed (not only directory links); hidden files and package contents are included; there is no block on searching `/` or the home folder, only the limits.
- `AgentPanel.routing_text()` (ui/panels/base.py:229-246) includes the text of every enabled QLineEdit/QTextEdit in the panel. While File Discovery is expanded (children enabled), clicking Auto-route feeds host, user, roots and filters to the local router (which only classifies text locally, services/benchmarks.py) and can change the chosen model.
- Dead code: `_image_osint` is never set (panel:127, 904, 922-923).
- Size column sort (row 67) and "250,001 checked" (row 72) cosmetic defects.
