# Requirements-traceability audit: Chat agent (`chat`)

Scope: README "Using the app" (Chat parts) and roster row, docs/agents/chat.md, docs/training/chat.md and workspace.md, config/tool_prompts.json, config/commands.json, ui/tooltips.py; plus docs/training/controls_settings.md, quick_start.md, docs/projects_roadmap.md and tests/manual_test_cases.md where they make Chat promises. Read-only review: nothing in the repo was run, edited or committed. Line numbers refer to the working tree at v2.002.

## 1. Verdict

Chat is substantially real: the five tools, Enter/Shift+Enter, multi-turn context, timestamped transcript, Stop, saved-chat rename/delete/agent filter, Chat Projects grouping, Auto-route and the BEST FIT/amber route cues are all backed by working code. It is not test-ready, though. Two defects stand out: with the default Execution mode (Local only) a cloud provider picked in the run bar is silently sent to Ollama, and in Hybrid/Cloud mode an unticked provider raises an exception that never reaches the user (also fired on every keystroke). The saved-chat model is weaker than documented: every turn writes a new snapshot file, so one conversation shows up as many identically titled entries, search is title-only, and a tool switch mid-conversation is silently ignored after turn one. Several promises are narrower than written (export is a whole-transcript .txt, not Markdown/HTML; Ollama does not stream; hover text on cloud entries is probably never shown; Speed-first routing equals Balanced), twelve tooltips sit on hidden widgets, per-tool recommended models in tool_prompts.json are dead config, and docs/agents/chat.md still describes a ChatAgent that does not do what it says. Project instructions/defaults/budget and any project management UI are absent (declared deferred in the roadmap).

## 6. (c) Undocumented behaviour a user would want to know

1. **Execution mode silently overrides the provider box.** Default is "Local only" with all provider permissions off, both hidden in Options. Picking a cloud provider/model in the run bar does not by itself route to the cloud (main.py:3226-3227). In Hybrid/Cloud mode an unticked provider makes Run do nothing visible (uncaught RuntimeError, main.py:3360) and the same exception fires on every keystroke through the live cost estimate (main.py:543, 2339).
2. **One file per turn.** Each completed turn writes a new `data/chats/*.json` containing the thread so far (history_store.py:15-16). A conversation therefore lists N times; deleting, renaming or assigning one entry leaves the other N-1; continuing from an opened old entry forks a new series.
3. **Tool is fixed after turn one.** The first turn's system prompt stays for the life of the conversation; the tool combo can be changed but has no effect on instructions (main.py:3419-3420). The system prompt is also displayed in the transcript as a SYSTEM block and saved.
4. **UI notices become model input.** "The request could not be completed ..." and "Chat request stopped by user." are stored as `system` messages and re-sent next turn (main.py:3899-3901, 3925-3927, 3297-3302). Anthropic's `_split` keeps only the last system message (anthropic_client.py:178-186), so after any error or stop the tool prompt is replaced by the notice; a failed prompt also stays in context; Gemini receives everything as one `role: text` blob.
5. **Cost is understated on follow-ups.** Pre-flight estimate, budget gate and (for OpenAI, DeepSeek, Gemini, Qwen streams that report no usage) the billed amount use only the newest prompt, not system prompt plus history (main.py:3362, 3856; services/usage_tracker.py:21-35). Anthropic and Kimi report real usage. A stopped or failed cloud request logs no cost.
6. **No history truncation.** The thread grows without limit and router context filtering sees only the newest prompt (main.py:3116), so a long chat can overflow a small local model's window.
7. **Typing triggers network and disk work on the UI thread.** Every keystroke runs the router twice (update_recommendation_label -> get_recommended_setup, then _recommendation_for), each calling `list_models()` (HTTP GET /api/tags, plus provider list calls for any ticked cloud provider, uncached), and `mark_oversized_models` calls `model_details()` (another /api/tags GET) once per entry in the model box (main.py:2340, 964, 1494-1499, 1541, 3108; ollama_client.py:58-95). Expect typing lag with many local models or a slow daemon; measure.
8. **Cloud confirmation every time.** Even with the provider ticked, each cloud request opens a Yes/No dialog showing estimated cost (main.py:3388-3394).
9. **Local-model memory guard.** Ollama requests are checked against RAM: "too big" blocks, "tight" asks for confirmation (main.py:713-736, 3399) and run_backend re-blocks too-big models (main.py:3740-3742).
10. **Scaffolds stick.** The selected Command (Options -> Command) is prefixed to EVERY message until changed, appears inside the YOU message and drives the saved title; it is independent of the Tool, so mismatches are possible.
11. **Hidden shortcuts.** Ctrl+Return sends, Esc stops (application-wide), F1 opens the Agent guide (main.py:376-386). With nothing running Esc appends "[Info] No running task to stop." to the Chat transcript widget even from another agent (main.py:3955). Enter is swallowed (no newline, no send) while a request is running.
12. **History includes other agents.** Records from Trace, Bug Spray etc. are listed; opening one switches to that agent without restoring it and loads its messages as Chat context (main.py:4460, 4469-4471, 3417).
13. **New chat / open during a run.** Neither cancels the running worker; its tokens and completion handler then rewrite the transcript and save a snapshot (main.py:3831-3849).
14. **Image/audio models selectable.** OpenAI image ids appear in Chat and generate an image file, returning "Image saved to <path>" (main.py:2859-2865, 3749-3751; openai_client.py:130-135); audio/realtime ids will just fail.
15. **Transcript is plain text.** No Markdown rendering, code indentation collapses, whole transcript re-rendered per token, assistant stamp = send time (see #13, #25, #23).
16. **Stop is a hard kill.** `QThread.terminate()` then a blocking `wait(2000)` on the GUI thread (main.py:3919-3920); late queued signals can still append text after the stop notice.
17. **Remembered model per provider.** Every model change (including programmatic reloads) writes `default_model_<provider>` to config/settings.json (main.py:2899-2915) and is restored when the provider is chosen.
18. **Project context does not isolate.** Changing the active project mid-conversation does not reset the thread; the next snapshot, including earlier turns, is filed under the new project. Project instructions/defaults/budget exist as DB columns but nothing reads them.
19. **Gemini and Ollama quirks.** Gemini loses role structure (flattened string); Ollama replies are non-streamed with a replay delay (see #20, #21).
20. **Settings -> Tools needs a restart.** Toggling a tool changes the registry at once but not the Tool combo (main.py:242-244 runs once); a disabled-but-listed tool then yields "Request Blocked".
21. **Live estimate chip.** The run bar shows `free / ~EUR x - N tok` for the current text and the Cost card mirrors it (main.py:586-617); not described in any Chat doc.
